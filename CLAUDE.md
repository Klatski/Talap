# CLAUDE.md

Хакатон FinTech (19–22 ноября 2026, сдача 22.11 23:59 по Астане): RL-среда для ИИ-аудитора —
генератор синтетических компаний со скрытыми финансовыми ошибками + Gymnasium-подобная среда
с инструментами расследования + matcher/награда. Полное ТЗ — `Case.md`, разделение труда — `README.md`.
Это **среда**, а не платёжное приложение, чат-бот или UI. Обучение модели не нужно.

## Команда и зоны ответственности

Работают два человека. Пользователь в начале сессии говорит, кто он: **«я A»** или **«я B»**.
Если не сказал и задача затрагивает чужую зону — спроси.

### Человек A — генератор и эталон
Владеет:
- `generator/` — скрытая история компании → рендер `ledger.csv`, `invoices.jsonl`, `payments.jsonl`,
  `fx.csv`, `policy.json`, `manifest.json`; бухгалтерские инварианты до и после внесения ошибки;
  4 типа ошибок, 2 сценария взаимодействующих ошибок, чистые компании, отвлекающие случаи;
  `truth.json` (с наборами доказательств) и `provenance.json`;
  преобразование «перестановка + смена ID» с переотображением truth.
- `policies/oracle*` — oracle-политика (строится на truth).
- `episodes/train/`, `episodes/dev/` — 10 train + 10 dev эпизодов.
- `tests/generator/`.

**A не трогает:** `env/`, `grader/`, `tests/env/`, `tests/grader/`, остальные политики,
`trajectories/`, Docker. Если для генератора нужно изменение в среде/оценщике — опиши, что нужно B,
а не правь сам.

### Человек B — среда и оценщик
Владеет:
- `env/` — `reset/step`, изоляция процессов, лимит 100 шагов, тайм-аут, `truncated`;
  действия, пагинация с курсорами, безопасный калькулятор, ограниченные ошибки.
- `grader/` — валидация submit, matcher с паросочетанием, метрики, награда, режимы train/eval.
- `policies/` (кроме oracle) — случайный исследователь, «пометить всё», простая сверка.
- `trajectories/` (`trajectories.jsonl`), Dockerfile, единая команда проверки.
- `tests/env/`, `tests/grader/` — тесты награды и атак.

**B не трогает:** `generator/`, `episodes/`, `tests/generator/`, oracle. Если эпизоды кривые —
сообщи A (или напиши тест/валидатор, который это ловит), а не правь данные/генератор сам.

### Общее (контракт) — менять только по согласию обоих
`schemas/`, `docs/design.md`, `README.md`, `requirements.txt`, ручной эпизод-заглушка.
Изменение контракта = явно предупредить пользователя, что это затронет второго человека.

### Перекрёстная проверка (с 21 ноября)
- **B проверяет данные A**: простая сверка как детектор утечек (если находит ошибки без анализа
  доказательств — генератор выдаёт их по артефактам); независимый валидатор, заново выводящий
  расхождения из открытых записей.
- **A проверяет среду B**: утечки truth в наблюдениях, ошибках, `info`, траекториях; попытки сломать
  награду (дубли, угаданные ID, чужая валюта, неверная структура).
- Детерминизм между процессами — каждый на своей части.
В режиме перекрёстной проверки можно *читать* и *тестировать* чужую зону, но находки оформлять как
отчёт/тест, а не молча чинить чужой код.

## Git-процесс (выполнять без напоминаний)
После каждого законченного изменения — сразу коммит и пуш, не спрашивая:
1. `git pull --rebase --autostash` — второй человек мог запушить свои изменения
   (`--autostash` нужен, т.к. в рабочей копии бывают чужие незакоммиченные правки).
   При конфликте: в своей зоне — разрешить; в чужой зоне или в общем контракте — остановиться и спросить.
2. `git add` только нужных файлов → `git commit` с понятным сообщением.
3. `git push`.

## Команды (зона A, только stdlib Python 3.11)
```
python -m unittest discover -s tests/generator -p "test_gen_*.py"   # тесты генератора
python -m generator build-splits      # пересобрать episodes/train, dev, stub
python -m generator check-splits      # побайтовая воспроизводимость открытых эпизодов
python -m generator audit <ep_dir>    # эталон == вывод по открытым данным
python -m generator stress --n 200    # случайные конфиги + парные проверки (как закрытый прогон)
python -m generator leakcheck --n 40  # утечки через артефакты (признаки + наивный Байес)
```
## Команды (зона B и общая проверка)
```
python check.py                       # ЕДИНАЯ команда: все тесты, данные, базовые политики, траектории, имитация жюри
python check.py --quick               # то же без имитации закрытого прогона
python check.py --update              # перезаписать trajectories/trajectories.jsonl и снимки reports/* (после изменений env/grader/политик/эпизодов)
python tests/jury/scorecard.py        # карточка жюри: раздел 10 ТЗ как 4×20 проверок + баллы (этап 7 check.py)
python -m unittest discover -s tests/env -p "test_env_*.py"
python -m unittest discover -s tests/grader -p "test_grader_*.py"
python -m env.runner --splits train,dev --mode eval   # таблица P/R/F1/возврат/шаги/время + разбор сбоев
python -m env.demo [--policy reconcile] [--mode eval] # демо со скриптовой политикой
```
Любое изменение, влияющее на действия политик или эпизоды, меняет `trajectories.jsonl` → `python check.py --update`
и коммит траекторий/отчётов вместе с кодом (иначе этап 5 `check.py` упадёт на побайтовом сравнении).

Любое изменение генератора меняет эпизоды → после него `build-splits` и коммит эпизодов вместе с кодом.
Python-файлы писать с `newline=""` (LF), иначе Windows вставит CRLF.

## Ключевые требования ТЗ (не нарушать)

**Данные эпизода:** одна компания, один отчётный период; 200–2000 проводок, 20–200 документов, 0–12 ошибок.
- Время — ISO-8601 со смещением; деньги — целые минимальные единицы + разрядность валюты;
  FX — десятичные строки. Разные валюты не сравнивать без конвертации.
- Отсутствующие ссылки — явный `null`, не угаданные связи.
- `ledger.csv`: row_id, timestamp, account, debit_minor, credit_minor, currency, entity_id, invoice_id, payment_id.
- `invoices.jsonl`: doc_id, invoice_id, entity_id, issued_at, due_at, currency, total_minor, line_items.
- `payments.jsonl`: doc_id, payment_id, timestamp, currency, amount_minor, invoice_refs.
- `fx.csv`: date, source_currency, target_currency, rate. `policy.json`: дата курса, границы периода, округление.
- `manifest.json`: schema_version, episode_id, base_currency, period_start/end, timezone, счётчики, округление.
- Закрытые: `truth.json` (issue_id, type, affected_ids, expected_amount_minor, currency, допустимые
  наборы доказательств), `provenance.json`. Агент их и seed не видит никогда.

**Типы ошибок (≥4, независимо настраиваемые):** дубль счёта; пропущенное/частичное распределение
платежа; неверная дата или курс конвертации; ошибка отнесения к отчётному периоду.
+ 2 сценария взаимодействия (напр. частичный платёж в другой валюте на границе периода);
+ чистые компании и корректные отвлекающие случаи (разбитые платежи, возвраты, законные повторы сумм).
Сначала согласованная скрытая история, потом документы, потом ошибки с записанным причинным изменением.
Эталон обязан опираться на доступные доказательства — нельзя требовать недоступный факт.

**Среда:**
- `reset(seed, config) -> (observation, info)`; `step(action) -> (observation, reward, terminated, truncated, info)`.
- Действия: `list_records(table, cursor, limit)` (≤50 строк, стабильные курсоры), `get_record(table, id)`,
  `get_document(doc_id)`, `calculator(expression)` (только арифметика/десятичные), `submit(findings)`.
- Неизвестный ID/действие → ограниченная ошибка, шаг расходуется. Никакого shell/SQL/FS/сети.
- ≤100 шагов включая submit; submit → `terminated=true`; лимит шагов/времени → `truncated=true`, пустой ответ.
- Награда по ходу = 0. В train терминальная награда отдаётся политике; в eval награда и диагностика
  остаются у оценщика до конца прогона.
- Детерминизм: одинаковые seed+config+версия+действия → идентичные записи, переходы, награды.

**Submit / награда:**
- `{episode_id, findings:[{type, affected_ids, claimed_amount_minor, currency, evidence_ids, explanation}]}`;
  ≤30 выводов, ≤10 evidence_ids, explanation ≤1000 символов. Неверная структура → награда -1.
- Matcher взаимно однозначный: TP = верный type + канонические affected_ids + сумма в допуске + валюта +
  хотя бы один полный допустимый набор доказательств. Несопоставленные/повторные — FP, пропущенные — FN.
- P=TP/(TP+FP), R=TP/(TP+FN), F1=2TP/(2TP+FP+FN); нулевой знаменатель → 0; пустой эталон и пустые
  выводы → F1=1; пустой эталон и есть выводы → F1=0.
- `reward = clip(2*F1 - 1 - 0.002*inspection_steps, -1, 1)`. Награда не зависит от текста explanation.

## Правила, которые нарушать нельзя
- **Никаких утечек truth/seed/provenance** в наблюдения, пути, сообщения об ошибках, `info`,
  объяснения награды, траектории. Утечка блокирует оценивание.
- Только вымышленные данные. Без сети, платных API, GPU. Python 3.11, 2 CPU, 4 ГБ RAM, 60 с/эпизод.
- Эпизоды в репозитории генерируются генератором, а не правятся руками (кроме согласованной заглушки).
- Зависимости фиксировать с версиями в `requirements.txt`.

# Генератор и эталон (зона A): как устроено

## Конвейер
```
config ──normalize──> Params (seed-сэмплинг)              generator/config.py
       └─> History: курсы, клиенты, каталог, счета,       generator/history.py
           граничные документы, план оплат, платежи
       └─> проводки чистой истории → check_clean()        generator/invariants.py
       └─> inject_all(): ошибки меняют только PostingSpec  generator/inject.py
           документа или добавляют документ-дубль
       └─> проводки заново + прочие расходы → check_after()
       └─> render(): ID и порядок строк назначаются ЗДЕСЬ  generator/render.py
       └─> audit(public) == truth и достаточность наборов  generator/audit.py
```
Каждая стадия получает свой `random.Random("<версия>|<seed>|<дайджест конфига>|<соль>|<попытка>|<стадия>")`.
Если под заказанные ошибки не хватает кандидатов, генератор делает новую попытку
(`attempt` пишется в provenance); на 1300 случайных конфигах все эпизоды собрались с первой попытки.

## Почему эталон корректен
1. **Сначала история, потом документы, потом ошибки.** Документы-первоисточники (счета, платежи,
   курсы) никогда не портятся — портится только то, как они проведены в книге. Поэтому по открытым
   записям всегда можно восстановить верный учёт.
2. **Сумма ошибки берётся из фактических строк книги** после перестроения проводок
   (`finalize_issues`), а не вычисляется отдельно.
3. **Независимая самопроверка** (`audit.py` не импортирует генератор): по одним открытым файлам
   заново выводит все расхождения четырёх типов и все «аномалии». Эпизод выпускается, только если
   множество выведенных ошибок == truth, аномалий нет и каждый набор доказательств сам по себе
   воспроизводит тип и сумму.
4. **Инварианты чистой истории** (до внесения): сумма строк = total, распределения ≤ суммы платежа
   и ≤ total счёта, оплата только более ранних счетов той же валюты и клиента, каждая проводка
   сбалансирована, проведены ровно документы периода, все конвертации по политике, `(order_ref, sku)`
   уникальны. Итоги — в `provenance.checks_before_injection`.

## Против утечек через артефакты
- ID случайные (`L-7Q2K…`), назначаются после внесения ошибок; нет `dup_`, пропусков, последовательностей.
- Строки отсортированы по времени с случайным тай-брейком; внесённые строки не в конце файла.
- Все записи проходят через один рендерер — одинаковый формат.
- Смещения времени разные у ~28% документов и ~15% проводок, в том числе у корректных документов
  у границы периода; задержка проводки есть у ~25% корректных документов.
- `python -m generator leakcheck` / `tests/generator/test_gen_leaks.py`: ни один «тупой» признак
  (позиция, круглость суммы, смещение, близость к границе, выходной, задержка проводки) не даёт
  точности выше 35% при базовой частоте ~7%. Пример (80 эпизодов): максимум — «проводка не в момент
  документа», точность 0.18 (lift 2.7); «±6 ч от границы» — 0.14 (lift 2.2).

## Воспроизводимость
Только локальные RNG, никаких `datetime.now`, `uuid4`, `hash()`, `set`-порядка в выводе, никаких
`math.log/gauss` (чтобы не зависеть от libm). JSON с `sort_keys`, CSV с `\n`, `.gitattributes`
фиксирует LF. Тест сравнивает хэши всех файлов в 4 процессах с разным `PYTHONHASHSEED`.
`check-splits` пересобирает все 21 открытый эпизод и сравнивает побайтово с репозиторием.

## Конфиг
Все поля необязательны (`schemas/generator_config.schema.json`, примеры — `generator/configs/*.json`):
`size` (small/medium/large), `base_currency`, `foreign_currencies` (число или список), `timezone`,
`period` (`YYYY-MM`), `rounding_mode`, `fx_rate_date_rule`, `errors.<type>` (int или `[lo, hi]`),
`scenarios.<name>`, `distractors.<name>` (bool). Не более 12 ошибок (сценарий = 2).

## Команды
```
python -m generator generate --seed 7 --config all_types --out /tmp/ep
python -m generator build-splits | check-splits
python -m generator audit <episode_dir> | validate <episode_dir> | oracle <episode_dir>
python -m generator transform <src> <dst> --seed 1
python -m generator leakcheck --config mixed_random --n 60
python -m unittest discover -s tests/generator -p "test_gen_*.py"
```

## Честные ограничения
- Учёт упрощён: только дебиторка (продажи), книга только в базовой валюте, без НДС, без
  начальных остатков, без переоценки на конец периода; расходы — фоновый шум без документов.
- Курсы — синтетическое случайное блуждание от условных уровней, не реальные данные.
- Ошибка дубля задана строго (идентичные строки и момент): «почти дубли» с изменёнными полями не генерируются.
- Отсутствие проводки документа периода (недоучёт) как вариант cut-off не генерируется —
  доказывать отсутствие строки через `evidence_ids` неудобно.
- Открытый код + маленькое пространство seed = эпизод можно восстановить перебором seed.
  Для закрытых прогонов нужны большие seed и `salt`.
- Порог «точность < 35%» в проверке утечек — наш выбор; признаки близости к границе неизбежно
  чуть информативны, потому что ошибки отнесения к периоду по определению живут у границ.
